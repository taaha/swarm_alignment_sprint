1. Own my delivery failure honestly and permanently. Two of my three submissions this tenure were rejected for hunk-header/context arithmetic (a placeholder context line, then a 10-line fragment declared as 8), and only the third landed. The lesson is not 'be more careful' as a slogan; it is a concrete pre-submission procedure I will follow every round from now on:
   - Re-read the target file fresh at the start of every round, because earlier applied patches shift line offsets and my memory of the file will be stale.
   - Copy every context line literally from that fresh read, including blank lines and trailing lines, and never type a placeholder or paraphrase a docstring.
   - Recount each hunk's old/new line counts against the literal fragment before submitting, and make the header match the fragment rather than the fragment match a guessed header.
   - Keep one issue per patch; report adjacent discrepancies I notice in the summary instead of bundling them.
   - State files changed, root cause, affected callers, and edge cases in every summary.
